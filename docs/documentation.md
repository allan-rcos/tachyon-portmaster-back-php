# Documentation

Source documentation is PHPDoc in `src/`, rendered to HTML by phpDocumentor.
Everything else — the why, the guides, the ADRs — lives here in `docs/` and in
the per-directory READMEs.

```bash
dagger call docs          # renders to docs/phpdocumentor
```

`dagger call docs` runs the `phpdoc/phpdoc` image against `phpdoc.dist.xml`;
there is no script to find a local binary any more, because the container always
has one. phpDocumentor is deliberately **not** a
composer dependency: its own Twig/Symfony constraints conflict with what the
application and PHPStan pin, which is why upstream ships a PHAR and an image.

Configuration is `phpdoc.dist.xml`. Output goes to `docs/phpdocumentor`, which
is **committed**: GitHub Pages serves this repository's `docs/` directory, so the
rendered reference is only published if it is in the tree. Only the render cache
stays under the gitignored `build/`.

## What gets documented

Everything hand-written under `src/`. **Not** the flatc-generated tables and
enums — `dagger call generate-fbs-php` overwrites those, so a docblock written into one
is lost at the next schema change. They are also the whole of `src/API/Fbs/`;
what the rest of the codebase actually talks to are the DTOs and factories under
`src/API/Negociation/`, which *are* documented.

The exclusion list is enumerated in `phpdoc.dist.xml`. Regenerate it after
adding or removing a schema:

```bash
grep -rl 'automatically generated by the FlatBuffers compiler' src | sort
```

The same boundary is drawn in `phpstan.neon`, whose baseline holds findings from
those files and nothing else.

## The format

Every file carries a **file docblock**, then a **class docblock**, then a
docblock on **every member** — constants, properties and methods, public and
private alike.

### File docblock

Immediately after `<?php`, before `declare(strict_types=1);`. The tag block is
identical in every file; only the title and `@category` change.

```php
<?php

/**
 * Product Table Module.
 *
 * @category Domain
 *
 * @license {@link https://opensource.org/licenses/MIT MIT}
 * @copyright 2026 Tachyon
 *
 * @filesource
 */

declare(strict_types=1);

namespace Domain\TableModules\Interno;
```

`@category` is the layer: `API`, `Application`, `Domain`, `Infrastructure`,
`Shared`.

The title is the humanised type name. Interfaces are `I<Thing>` and their file
is the contract, so the `I` is dropped and "Contract" appended —
`IProductTM` → *Product Table Module Contract.*

### Class docblock

One sentence saying what the type is for, then a paragraph only if there is
something a reader could not infer. Cross-reference rather than repeat:

```php
/**
 * Builds validated products, and refuses to build invalid ones.
 *
 * @see IProductTM The contract this implements.
 * @uses IDatabaseIdGenerator Supplies the product id.
 * @see docs/adr/0003-engine-memory-for-runtime-tables.md Why the registry is in RAM.
 *
 * @license {@link https://opensource.org/licenses/MIT MIT}
 * @copyright 2026 Tachyon
 */
```

### Member docblock

```php
/**
 * Builds a validated product.
 *
 * @param  string  $name  Commercial name; must not be blank.
 * @param  float  $density  Kilograms per litre.
 * @return Result<IProduct> A 422 failure when a rule is broken.
 *
 * @copyright 2026 Tachyon
 *
 * @api
 */
```

`@api` marks the members that are the type's public surface — the ones a caller
in another layer uses. Not every public method: an accessor that exists to
satisfy an interface is not `@api`.

### `@api` and `@internal` are a pair

They divide the codebase along the same seam, so decide them together:

| | Contract (`I*`) | Implementation (`Interno/`) |
|---|---|---|
| Class | — | `@internal`, last tag |
| Members | `@api` on the public surface | **no** `@api` |

An implementation is reached through its interface, so its methods are not
anyone's API even when they are `public`; the contract's are. Putting `@api` on
both says the caller may bind to the concrete class, which is exactly what the
`Interno/` split exists to prevent. `Domain/Models/Internal/` follows the same
rule despite spelling the directory in English.

`@internal` also has a rendering consequence worth knowing: phpDocumentor
**omits** tagged elements from the HTML unless `--parseprivate` is given.
`dagger/modules/docs` passes it by default, so the implementations stay
visible — `dagger call docs --contract-only` renders the contract-only view.

## Rules

**No `@since`, `@version` or `@author`.** Git already records who touched a line
and in which release it landed, and a hand-maintained copy of that only goes
stale. `@license` and `@copyright` stay — they say something git does not.

**Never delete a PHPStan generic.** `@template`, `@extends`, `@return Seq<T>`,
`@return Result<TItem>`, `@var list<...>` carry typing that level 9 depends on.
Rewrite the prose around them. `dagger call phpstan` is the check that this was
respected, and it must stay clean.

**Say what it does, not what it is.** "Builds validated products" beats "Product
table module class that implements the product table module interface". If
removing a sentence loses nothing, it was noise.

**No invented rationale.** If you do not know why something is the way it is,
document the behaviour and leave the why out. A confident wrong explanation is
worse than none.

**Deep rationale goes to an ADR.** Long "why we do it this way" passages belong
in [`adr/`](adr/), referenced from the docblock with `@see`. A class docblock
that runs twenty lines is an ADR that has not been written yet.

## The initial pass

Done. Every layer of `src/` — `Shared`, `Domain`, `Infra`, `App` and `API` — has
been through this format, so the per-file ledger that tracked it is gone and the
`phpdoc` skill is maintenance-only: it works over changed files, not the whole
codebase.

The flatc-generated tables under `src/API/Fbs/*/` are the standing exception.
They are excluded rather than documented, because `dagger call generate-fbs-php`
overwrites them; the DTOs and factories in `src/API/Negociation/` that stand in
front of them are documented instead.

## Keeping it aligned

Documentation does not have to be perfect at the moment code is written. The
`phpdoc` skill exists to make a pass afterwards and bring a file up to this
format — that is the intended workflow: write the code, then align the docs.

```bash
dagger call phpstan && dagger call docs
```
