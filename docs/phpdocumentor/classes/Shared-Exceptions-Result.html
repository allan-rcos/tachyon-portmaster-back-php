Result.php : 40

The return type of every operation that can fail.

A Result is either a success or a failure carrying an error id — never both, and never neither. A success usually carries a value; void() is the one that carries nothing, and means "no error", never "the value is null". Failures travel as ids rather than as thrown exceptions so a use case can decide what to do with one without unwinding the stack, which matters when the boundary in between is a database transaction that must be rolled back rather than abandoned.

The id indexes into Leaf, which holds the LeafContext carrying the message, details and HTTP status. Keeping that context out of the Result is what lets a failure be typed Result<never> and so satisfy any signature it is propagated through.

void()

Result.php : 119

A success with nothing to return — the shape of a command that worked, and of a question whose honest answer is "nothing", such as a lookup that matched no row where matching none is not a fault.

public static void() : Result<string|int, never>
APIYes

It means no error, and never "the value is null": a null on a success carries no information, so nothing should read one. Ask isEmpty() instead, then take the branch.

Typed Result<never> for the same reason failure() is: carrying no value, it satisfies a signature of any type, so a method declared Result<IProduct> can answer one without widening to IProduct|null.
