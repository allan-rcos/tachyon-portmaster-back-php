JwtConfig.php : 40

Session token settings.

Lives in the API layer because JSON Web Tokens are a presentation-level transport decision: how this application happens to carry a session over HTTP. Nothing in App, Domain or Infra knows the session is a JWT, or a cookie, or a token at all — they only ever see a UserContext.

The access token travels in an HTTP-only cookie (never the Authorization header), so it is unreachable from JavaScript; the protection comes from the cookie flags: HttpOnly (XSS), Secure (HTTPS only) and SameSite (CSRF).

Resolved from the environment at bootstrap (see DotEnvStarter) and injected, so no service reads env.

Parameters
$secret : string = ''

Signing key for the HMAC algorithm. The empty default is a working local configuration and an unusable production one.

$ttlSeconds : int = 3600

How long an access token stays valid. Short by design; the refresh token below is what avoids the logout.

$issuer : string = 'tachyon/portmaster'

Value of the iss claim, checked on verify.

$algorithm : string = 'HS256'

JWS algorithm name.

$cookieName : string = 'auth_token'

Cookie carrying the access token. Must match the CookieAuth scheme documented in swagger.json.

$cookieSecure : bool = false

Whether both cookies carry Secure, which confines them to HTTPS. Off by default so local HTTP works.

$cookieSameSite : string = 'Strict'

SameSite attribute for both cookies.

$refreshCookieName : string = 'refresh_token'

Cookie carrying the refresh token. Long-lived by design: it is what lets the short-lived access token expire quickly without logging the user out. The token itself is signed and carries the same principal — the HttpOnly flag, not opacity, is what keeps it away from scripts.

$refreshTtlSeconds : int = 1209600

How long a refresh token stays valid.
