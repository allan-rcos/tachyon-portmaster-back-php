IManifestRepository
in
  • Portmaster

IManifestRepository.php : 49

Persistence for what a container carries, and for what happened to it.

Two tables behind one contract: the cargo lines that make up a manifest, keyed by container and product together, and the append-only telemetry log beside them. Both cascade from containers, so deleting a container through IContainerRepository takes its manifest and its history with it and nothing here needs calling first.

Stores what the table module already validated — capacity, weight and the rest are decided before anything reaches here. Every method enlists in the caller's open transaction.

public upsertCargo(IManifestCargo $cargo) : Result<string|int, null>
APIYes

Deletes then inserts rather than issuing an upsert, so the stored line is exactly what was passed in and no previous column survives. Both statements are in the caller's transaction, so the line is never observably missing.

Parameters

Carries both ids and the resulting quantity and weight, already validated.
